# Corporate Documents

## Scope

Corporate Documents appears under Compliance → Manage/View Companies → an existing company profile. It does not alter company information or employee signature workflows. The only categories are EIN, Articles of Incorporation, Operating Agreement, Bylaws, Certificate of Good Standing, and Other Corporate Document. No expiration dates are collected.

Every category supports multiple independent PDFs. Replace creates a new version and retains the old PDF in Replaced history. Delete is a soft deletion: it hides the selected record and denies its view/download routes; bytes remain in private database storage for recovery/audit purposes. Deleting a current version does not automatically reinstate an older version.

## Schema and storage

`backend/app/models/corporate_document.py` defines `corporate_documents` with a foreign key to the existing `compliance_companies.id`. Upload attribution references `employees.timestation_id`, the existing canonical user identifier used by authentication and audits. Metadata includes company_id, document_type, original_file_name, generated unique UUID storage_key, uploaded_by_user_id, uploaded_at, optional notes, status and replaced_document_id. PDF content is a database LargeBinary/BYTEA column, matching existing compliance PDF architecture. No public disk directory or object URL is generated by the server; client download Blob URLs exist only in the authenticated browser and are revoked.

`backend/app/models/corporate_document_migration.py:ensure_corporate_document_schema` is an additive, idempotent SQLAlchemy migration invoked by application startup after the legacy compliance schema guard and creation of existing-model tables. The generic create_all excludes the new table so its creation is owned by the explicit migration. No old migration is modified and no company rows are inserted or updated by it. Foreign keys, unique storage keys, exact-category, status, and notes-length constraints are applied on creation.

The migration is backward-compatible with the previous application: an application rollback can leave the additive table in place. Do not drop it after uploads have begun. A database backup includes corporate PDF bytes and metadata; preserve the existing document filesystem backup separately for employee documents.

## API

Base: `/api/compliance/companies/{company_id}/corporate-documents`

- GET base: visible current/replaced metadata, exact category list, can_edit.
- POST base: multipart file, document_type, optional notes; returns new document, HTTP 201.
- GET `/{document_id}/view`: authenticated inline PDF; records view audit.
- GET `/{document_id}/download`: authenticated attachment PDF; records download audit.
- POST `/{document_id}/replace`: multipart file/optional notes; HTTP 201; atomic new version and old status transition.
- DELETE `/{document_id}`: soft-delete current or replaced record; HTTP 204.

Each route requires existing compliance authentication, company access and a document lookup scoped by both company_id and document_id. Super admins can access all companies; admins require the existing CompanyPermission grant. Writes additionally require can_edit and an active company. Employees/managers without compliance access are denied. Disabled sessions and revoked company permissions are rechecked by existing authentication/authorization on each request. New document operations never implicitly create the default company.

PDF responses are private/no-store, no-cache and nosniff; Content-Disposition is safely encoded. Server validation checks .pdf extension, application/pdf MIME, %PDF- signature and actual PDF parsing, rejects encrypted/empty/unreadable PDFs, caps reads at 20 MiB and notes at 4,000 characters. Storage keys are generated independently of filenames. Uploaded filename metadata is normalized, not used as a storage path.

## Resource and concurrency protection

Corporate upload/replace bodies are capped at 21 MiB before multipart parsing, including actual chunk-byte accounting. PDF parsing runs in at most one isolated child process per API process, with a 128 MiB memory cap, 5-second CPU cap and 8-second wall-time cap. Validators accept at most 250 pages, 8 MiB decoded resources per page, 32 MiB aggregate decoded resources and 50,000 visited objects. Saturation fails fast rather than queueing PDFs. Isolation setup failures fail closed; timeout/cancellation kills and reaps the child. Linux uses RLIMIT and Windows uses JobObject limits. Execution evidence and platform verification limitations are recorded separately.

After validation, operations freshly recheck employee role/login, company and applicable permission under PostgreSQL FOR SHARE row locks, held through the operation/audit commit. Preliminary transactions are released before validation. This serializes authorization against ordinary archive, grant-revocation and employee-state writes without modifying company data.

PDF.js decoder/fallback files, CMaps, standard fonts and licenses are emitted from the pinned dependency by the Vite asset plugin and served same-origin. No decoder CDN is used.

## Audit

Existing ComplianceAudit records actions `corporate_document.upload`, `.view`, `.download`, `.replace`, `.delete`, with company, user and timestamp in existing columns and document/version identifiers in structured old/new values. No PDF bytes, storage keys, filename or notes are copied into the audit. Mutations and audits share one transaction; view/download fail closed if their audit cannot be committed.

## UI and PDF renderer

CorporateDocuments is a sibling of the company form, avoiding nested submission or accidental profile saves. API queries and captured action URLs are company-ID scoped. Switching companies aborts pending work and removes the viewer. PDF.js and its worker are bundled locally; the viewer renders canvas pages in-app with page controls, zoom, fit-width, close/Escape, focus handling and responsive layout. No external document rendering service receives PDF data.

The frontend build uses Node 22 to satisfy pdfjs-dist 6.3.289's supported engine. Runtime remains Python 3.11. Backend adds pypdf 6.19.0.
